# 作業截圖指引（建議 5 張，主圖 3 張即可）

所有截圖都應使用**你自己的實際畫面**。網站發布前可先截本機成果，但「公開網址證明」務必使用上線後的 GitHub Pages 網址；不要將本機 localhost 截圖描述成已公開發布。

## 必截 A：首頁網站成果（01-home.png）

- **去哪裡：** 已發布的 GitHub Pages 網址 `/interaction-notes/`。
- **畫面範圍：** 保留瀏覽器網址列，至少拍到「交互筆記」品牌、主標題「把複雜知識，整理成能延伸的學習筆記」、導覽列和首屏主視覺。
- **說明文字：**「網站首頁：以 HCI × AI 學習筆記為主題，首頁呈現專案介紹、內容分類與精選文章。」

## 必截 B：AGENTS.md 規則（02-agents.png）

- **去哪裡：** GitHub Repository 的 `AGENTS.md` 檔案頁。
- **畫面範圍：** 保留 GitHub 網址或上方儲存庫名稱，拍到 `AGENTS.md` 檔名，以及「專案目標」「目錄結構」或「筆記資料 Schema」其中一段。
- **說明文字：**「AGENTS.md：定義專案目的、統一視覺、資料結構及 AI 新增內容的操作規則。」

## 必截 C：功能展示（03-library.png）

- **去哪裡：** 公開網址的 `library.html`。
- **操作：** 點「人工智慧」分類；畫面保留網址列、分類按鈕的選取狀態和篩選後的筆記卡片。
- **說明文字：**「分類篩選：可依人機互動、人工智慧與研究方法瀏覽，所有文章共用卡片樣式。」

## 加分 D：文章模板（04-article.png）

- **去哪裡：** 點一張卡片進入 `note.html?id=ai-rag-intro`。
- **畫面範圍：** 顯示文章標題、分類、摘要、兩個以上章節的起始內容及瀏覽器網址列。
- **說明文字：**「文章內頁：利用同一個 note.html 搭配不同資料 id，自動顯示對應內容，新增筆記不需要重做 HTML。」

## 加分 E：GitHub Pages 部署證明（05-pages.png）

- **去哪裡：** GitHub Repository → `Settings` → `Pages`。
- **畫面範圍：** 顯示發布來源 `main / (root)` 與完成後的網站網址（或 Visit site）；不要顯示個人敏感資訊。
- **說明文字：**「GitHub Pages：專案由 main 分支根目錄公開發布，網站可直接透過連結瀏覽。」

## 截圖技巧

- Windows：`Win + Shift + S` 選取畫面；可用 `Win + PrtScn` 擷取全螢幕。
- 建議瀏覽器縮放 90%～100%，讓重點文字完整入鏡。
- 若老師只允許少量附圖，優先提交 **A、B、C**，並讓文字說明補充文章模板與發布結果。
- GitHub Pages 建立後再截 A、C、D、E，確保地址列可見、連結也能正常點開。
